# What is in `docs/`

| folder or file | what it holds |
| --- | --- |
| `spec.md` | the product specification the build works from: what the app must do, and the rules it must not break |
| `decisions/` | numbered decision records. **Why**, not what. Read these before changing anything they cover |
| `licences/` | third-party licence texts, filed verbatim, with their sources and hashes |
| `demo/` | the run of show for the 26 September demo, the countdown, the device queue, and the audit of the deck's claims against the code |
| `design/` | the interface research, the design system, and the per-beat frame-timing measurements |
| `localisation/` | the Telugu review packet, the string conventions, and the record of every machine-generated line |
| `screenshots/` | dated screenshots of real builds, kept as evidence for the claims made elsewhere |
| `submission/` | the hackathon form answers and the checklist run before the repository went public |
| `review-packets/` | a review packet from an earlier phase, kept because its findings are still cited |
| `handover-priya-2026-09-21.md` | one session's handover of the conversation and knowledge layer |

The two documents at the repository root belong with these: `HANDOVER.md` is what a new person
reads first, and `COORDINATION.md` is the working log the sessions wrote as they built.
